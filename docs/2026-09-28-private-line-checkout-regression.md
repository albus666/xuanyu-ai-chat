# 私人专线确认页可靠性

## 范围

只修改 `PrivateLineCheckoutPage`，保留原费用规则、支付选择、老师卡片和整体样式。不修改通话页面或支付签约页面，不执行真实支付。

## 已复现与实现

原页面的 7 项红测全部失败：加载中可操作、支付配置失败伪装成未开通、同帧双提交、业务失败夹带 ID 仍进入、切号后的迟到成功继续回调、进入回调失败后重新创建、创建 500 后盲重试。

- 支付配置、余额与平台配置全部校验业务成功；失败或畸形余额展示重试，不把未知状态当作未开通，加载完成前禁止发起。
- 页面生命周期固定账号认证；账号变化时清空余额/待进入 ID、失效所有在途响应。每次跨异步边界检查，旧页不调用房间切换或跳入旧账号咨询。
- 函数级提交锁覆盖支付开通/充值提示、创建咨询和进入通话全过程，同一帧重复点击也只提交一次。
- 创建成功立即保存 sessionId，再执行房间/音频回调。回调失败后“继续进入咨询”只读校验同一 ID，不再次创建；已结束或不匹配的咨询禁止进入。
- 超时、500、409 或成功体缺有效 ID 时，保留“待核对”状态，不直接重试创建。用户可点击只读核对，严格匹配老师、模式、房间、付款方式及进行中状态；没有唯一匹配时提示去“我的咨询”核对，不把空列表当成可以再扣一次。
- 余额不足的充值确认在切号后失效；支付宝的 402 不误显示成玄遇币充值提示。

## 验证方式

`flutter test --no-pub test/features/consultation/private_line_checkout_reliability_test.dart`

新增 17 项 Widget 回归全部通过，所有请求均由本地 Dio 拦截器响应，账号与会话均为合成数据。包括正常成功进入实际通话页面、失败重试、重复点击、多个切号时机、配置异常、未知结果恢复、错误老师/房间/付款方式/终态拒绝。最初 7 项失败均已由红转绿。

`flutter analyze --no-pub lib/features/consultation/private_line_checkout_page.dart test/features/consultation/private_line_checkout_reliability_test.dart`

两文件静态分析与 `git diff --check` 均通过。主代理另行进行本轮跨模块合并回归，并统一提交推送。

## 未覆盖边界

- 不等于真实扣费、支付宝签约、双机声网语音、断网/杀进程后的持久恢复已验收。
- 此页 pending sessionId 保留于当前页面；重新进入时后端已有进行中咨询会阻止再创建，遇到 409 后再只读核对，不宣称实现全应用持久幂等键。
- 支付设置子页自身的保存/签约生命周期仍需另批审查；本段只保护确认页发起及从子页返回后的流程。

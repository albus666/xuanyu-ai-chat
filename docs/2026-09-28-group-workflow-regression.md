# 申请邀请、群成员与群聊部落中心定向回归

日期：2026-09-28；全 APP 排查第四批第一段；目标版本：`1.0.16+17`。

## 复现与修复

首轮五项界面测试均在修改前失败：申请列表网络失败误报“暂无记录”；隐藏接口跳过的记录也被从界面移除；邀请候选人加载失败误报“暂无可邀请的人”；邀请接口 HTTP 200、业务码 403 仍提示成功；360 宽度下长昵称叠加管理员、禁言、实习标签溢出。修复后五项通过，随后扩大测试。

1. **申请与邀请加载**：七路列表分别记录成功/失败，一路失败不遮蔽其他记录；刷新失败保留已加载内容，并显示重试。空列表同样可以下拉刷新。私聊申请、入群申请、邀请按明确类型处理，不混用编号和接口。
2. **记录删除**：只接受服务端确认的隐藏数量和跳过清单；跳过项保留，未知或矛盾结果提示刷新确认。超过 100 条按接口上限分批；后续批次失败保留剩余项，不撤销已成功结果。已确认隐藏的记录不会被迟到的刷新副本重新显示。左滑、批量和清空沿用原确认说明，仅隐藏自己的处理记录，不改变成员关系。
3. **申请处理**：同意、拒绝、撤回、再次申请增加操作锁与业务成功校验；确认框期间也属于一次操作。提交理由保留、去首尾空格；对话框改用随组件销毁的输入状态，避免关闭动画期间使用已销毁控制器。
4. **邀请成员**：加载失败可重试；候选人去重并排除已有成员；发送期间不可重复点选和提交。只有业务成功才反馈邀请结果，统计隐私限制、其他部落占用、无效账号等跳过项。全部跳过时留在页面；至少发送一条邀请才返回并通知上页刷新，邀请不当作已经加入。
5. **成员管理**：加载/刷新失败不会保留可用的旧权限；普通成员、管理员、群主按现有规则显示操作。移出、转让、管理员设置、禁言、撤销邀请、部落职能与阶段设置共用防重复和权限检查；确认后再次检查状态。转让成功先撤下旧权限，再读取新成员状态；刷新失败仍不可继续使用旧群主操作。401/403/404 撤下权限并使旧刷新响应失效。
6. **账号隔离**：一次操作固定发起时的认证与会话。切号前的确认不能用新账号提交，旧响应不能回填或跳转。申请/群部落中心清空旧列表并重新加载；具体群成员/邀请页清除旧数据，提示返回后重新进入。创建页返回结果也检查发起会话，但创建页自身的完整流程留下一段。
7. **布局和反馈**：长昵称及多个成员标签自动换行，不再横向溢出；我的群聊卡片使用 Material 绘制点击反馈，保持原白色、圆角和边框。社区中的部落标志位置和身份规则未改，不增加平台审核。

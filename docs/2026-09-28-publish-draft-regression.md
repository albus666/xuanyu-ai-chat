# 社区草稿与后台发布定向回归

日期：2026-09-28；全 APP 排查第三批第二段。目标版本：`1.0.14+15`。

## 复现和修复

- 先用失败测试复现：账号甲保存的草稿出现在账号乙的发布页；视频文件丢失后仍发送纯文字帖子（预期 0 次发帖，实际 1 次）。
- 草稿按账号隔离，游客单独保存。返回原账号可以继续编辑；草稿快照在异步操作前捕获，退出页面后不再读取已销毁的输入控制器。
- 图片、视频、已有录音及其时长随草稿保存；附件流式复制到应用支持目录，内容哈希去重。普通缓存清理只清临时目录，不清这些副本。成功发布/用户丢弃后只回收本账号、不再被任何草稿或任务引用的副本，不删除相册原件。
- 保留可见范围、评论权限、位置、组件、话题与提及 ID；删除正文中的实体后不发送失效关联。
- 先保存完整草稿再检查/发布，转为独立的未完成任务后才离开编辑页。连续点击不会重复提交；迟到的页面自动保存不能让已进入发布队列的同一草稿复活。
- 发布页有失败记录时显示“未完成发布（N）”。恢复只回到编辑页，不自动发帖；当前编辑稿另存为恢复记录，避免覆盖。没有失败记录时不增加这个入口。
- 网络请求固定任务创建时的账号及会话。切号后停止继续上传、确认、查询或发帖；已经在服务器提交的旧任务只清理自己的记录，不影响后来新建的稿件或另一个账号。
- 发布前校验附件完整性；丢失附件、混用互斥媒体、上传失败、确认失败、HTTP 拒绝、业务失败都不能继续发出不完整作品。
- 发帖超时、异常响应或进程在发帖阶段结束的记录标为结果待确认，恢复前提醒先查看自己的作品，避免重复。没有实施后台自动重发。
- 通知关闭/插件不可用不阻断发帖，也不把已经成功的作品误判成发布失败。账号切换后不再展示旧任务的成功/失败通知。
- 空白返回不弹草稿选择，连续返回只处理一次；保存/读取失败不覆盖旧记录。

## 旧草稿处理限制

旧版 `community_post_draft_*` 数据没有保存所属账号，无法可靠判断所有者。本次保留原数据，不删除、不认领给当前登录人，也不在其他账号自动显示；归属核验和旧数据恢复仍需单独处理。不能把“原始数据仍保留”解释成已完成旧版草稿无损自动迁移。

## 验证

- 新增 `publish_isolation_regression_test.dart` 的 26 项回归：包含跨账号界面切换、失败记录恢复、覆盖保护、正文检查拒绝、连续点击、退出页面，以及本地存储、媒体完整性、通知失败、任务归属和请求载荷验证。
- 其中 2 项使用 `127.0.0.1` 本机 HTTP 服务真实接收附件字节，分别返回上传成功与失败；业务 API 由测试拦截，不向线上发布。
- 联同系统返回、原有发布布局/设置、位置、话题与提及、上一段评论/搜索、详情布局和分享回归，共 **50 项通过**。已有布局测试内地图请求由 Flutter 测试环境阻止，不代表地图服务故障或真机地图已验收。
- 草稿存储、后台发布、媒体查询适配和新增测试 4 个文件静态检查无问题。发布页没有编译错误，仍有 38 条既有未使用旧界面代码/弃用 API 等提示，未扩大本次任务去重构。
- 只读核对后端发帖成功返回 `data.id`；没有修改后端、部署服务、真实发帖、给用户发消息、删除线上数据或支付。

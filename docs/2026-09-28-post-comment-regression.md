# 帖子详情与评论权限定向回归（2026-09-28）

## 范围与复现

本段仅处理帖子详情及关联评论交互，不改变发布规则、部落答疑身份、分享样式或菜单布局。

先建立 8 条 widget 红测，全部复现失败：评论发送业务失败清掉草稿、删除失败错减数量、赞/踩业务失败保留错误的乐观状态、采纳失败显示已解决、详情或评论被拒后继续展示缓存正文、切换账号后旧正文与草稿残留。删除评论菜单同时触发了 ListTile 的背景遮挡反馈断言。

## 修复

- 使用固定认证会话的 `ImWorkflowRequest`，检查 HTTP 成功响应中的业务码。失败时不清草稿、不假减评论数、不标记已采纳，赞踩回滚原状态。
- 同一评论的赞/踩/删除采用操作锁，采纳采用页面锁，防止连点或互斥动作并发。
- 删除确认成功后立即按 ID 移除本地条目并只扣一次数量；随后刷新失败也不再留着可重复删除的旧条目，不改变原有父子评论规则。
- 详情与评论读取明确返回 401/403/404 后清除旧正文、评论、回复目标及草稿。过期读取结果不能把内容重新带回来；页面保留返回及重试入口。
- 动作被拒不直接等同于原帖不可见：先保留草稿并重新读取原帖。关闭评论的 403、回复对象已删除的 404，在原帖仍可见时不清原帖或草稿；只有详情也确认不可访问才清缓存。
- 账号切换立即清除旧正文、评论及草稿。评论发送、删除确认、采纳及赞踩不能借用新账号认证。页面自有的删除帖子、不感兴趣、关注、私聊等保留入口也增加会话检查；返回后的过期结果不再更新此页。
- 正常发送保留已有“慢网期间继续输入的下一条草稿”行为，并刷新评论；正常采纳即时更新；赞踩采用接口返回值。旧详情读取不能回退刚更新的评论数量或采纳状态。
- 评论删除菜单仅将原白色容器换为同色 Material，维持外观与布局，恢复点击反馈。

# 全款预售（2026-10-05）

范围：自营实体商品全款预售。一次支付商品价及运费，无定金/尾款。旧商品默认现货，部署不自动上架商品或修改库存。

## 运营操作

管理后台「商城与善意回声 → 商品 → 销售/预售设置」配置批次、开始/截止/最晚发货时间、每人限购、规格价格及剩余名额增减。填写北京时间。SKU 库存即剩余可售名额，待付款订单也占用。保存使用商品更新时间防止重复提交增减名额和覆盖其他管理员设置。新增商品仍通过既有商品管理入口完成。

已有预售订单的商品不能换批次或改为现货；新批次新建商品，避免旧批次退款串入新批次库存。订单快照不随商品改价、改时间而改变。关闭销售使用下架；下架不取消已有订单的履约承诺。预售不能用于赠礼审批。

「全部订单」支持预售/逾期/超时付款退款中筛选，按原承诺最晚发货日期判定逾期。待发货预售单可填写延期说明和新预计时间，保存后站内通知用户，重复相同内容不重复通知；原承诺不覆盖。用户可从订单申请售后。

## 购买与状态

商品列表标记预售，详情显示批次、限购、预售时间、最晚发货、全款及退款说明。预售直接购买，不与现货/其他预售商品合单。结算必须主动确认规则。

报价签名绑定用户、规格、数量、价格、运费和预售规则，有效30分钟；变更需重新结算。旧客户端没有报价确认则不能创建预售单，普通现货兼容。

下单按用户行锁、商品行锁、规格行锁顺序处理，保存请求幂等编号；相同请求重试返回原单。预售名额按SKU扣减，限购累计同批次有效订单（含待付款，不含取消、全额退款、超时付款退款中）。待支付有效期取30分钟与预售截止的较早时间。

正常付款 → 待发货 → 已发货 → 收货/售后。退款处理中禁止发货。未发货仅退款确认成功才归还名额，重复退款不重复回补。未付款取消/超时只释放一次。

付款渠道首次选择后固定，同订单不交叉切换渠道。取消/超时后收到签名及金额校验通过的支付通知 → 超时付款退款中 → 原路退款；不重新占库存。退款请求先持久化，再调用渠道，超时重试沿用原编号。渠道明确关闭或异常需要财务核查，不能显示成退款成功。

## 定时任务与部署

后端 shop 0008、0009 为增量迁移。既有 `xuanyu-shop-order-expiry.timer` 负责未付款到期释放。
新增 `xuanyu-shop-presale.timer` 每分钟调用 `process_shop_presales --apply --limit 100`：
- 未发货超过原承诺日期，站内提醒一次；已发货售后不误判为发货逾期。
- 仅处理业务状态 `refund_pending` 且支付主单记录 `lateShopPayment` 的自动补偿，不扫描所有历史资金单。
- 命令不加 `--apply` 只读。

Django 订单页改为只读，发货/退款走运营接口，防止直接改状态绕过资金检查。预售价格/名额经专用配置入口修改。

## 验证与边界

本次在全新隔离 MySQL schema 执行并发和真实 ORM/事务测试，HTTP 被拦截，支付渠道返回合成成功/处理中/超时结果；不生成生产测试订单，不动真实余额。测试包括限购、多SKU、最后名额、同请求重试、重复付款回调、取消竞态、报价篡改和变价、退款恢复库存、延期权限与通知等。

前端测试覆盖告知确认、报价和幂等编号、失败重试、账号切换、退款中状态、北京时间及320宽大字；既有商城回归一起执行。

待外部验收：真机微信/支付宝收银台、渠道真实签名回调/退款到账、断网及杀进程恢复。隔离测试不替代这些验收。当前不含定金尾款、跨商品混合预售、分批发货、多商户预售或自动退款赔付。支付/退款异常由财务沿用原退款请求核对，不能重新开新单重复退款。

# 没一句好话 · 慢半拍第一版

状态：已按用户要求从当前客户端彻底移除页面、路由与专用代码。本文仅保留历史设计记录。

功能：用户输入一件事，得到今日状态、具体吐槽、一件小行动和独立的第一人称分享文案。恋爱、工作、生活均可。无需填写或读取出生资料；不把今日状态当作固定人格判断。

## 界面与素材

沿用用户确认的米白陶质慢半拍、一字眉、红杯子。奶油纸色底、墨色正文、砖红点缀。结果为正常纵向阅读；分享图为3:4竖版，只含状态名、嘴替短句、角色、玄遇署名及AI提示。分享先预览再调用系统面板；复制也保留AI标识。

素材：`assets/roast/manbanpai.png`。使用内置image_gen工具，参考用户确认的原图，生成透明底单角色；保留原始生成文件。提示词：保持米白陶瓷、不对称修长身体、一字眉、半闭眼、弯曲头发、单手叉腰、红杯子及原姿势；去掉背景、文字和小重复角色，输出真正透明PNG，不增加道具。

首屏不显示力度选项；生成后才提供温柔一点、再损一点。语气调整使用上一次成功提交的经历，不误读输入框后来改写的内容。换角度只切换同批候选，不新增模型调用。

## 协议与失败状态

POST `/api/fortune/roast/generate` 新客户端传 `schemaVersion: 2`、`eventText`（2–120字）与`intensity`。不传八字。旧协议继续服务旧安装包。

v2输出schemaVersion、mode、candidates；候选包含id、headline、body、action、shareText、mood、aiGenerated。服务端校验字段、事件锚点、重复候选及分享文案中的常见联系方式。分享前仍需用户检查，不能宣称自动脱敏已覆盖所有真实姓名和隐私形式。

同一账号同一经历/语气复用两小时Redis缓存，不跨用户共享。按账号限制同时运行的模型请求。错误不缓存为成功，不调用旧版模板兜底，不生成图片。客户端45秒超时，页面销毁或切号取消请求并清除旧内容。

高风险关键词在模型调用前转支持性固定回应；模型也可把间接危险表达判为support。支持态不显示毒舌语气、复制、分享按钮。关键词与模型判断并非完整危机识别系统。

## 本轮边界

本轮先上线固定主角静态版；mood为后续动作素材保留字段，不把尚未绘制的六套动作当成已交付。微信动态表情包的制作、投稿和审核是独立工作，不等于APP中调用系统图片分享。

当前不新增付费、扣次数、真人咨询导流，也不将内容作为心理诊断或八字推断。不宣称达到百万并发或保证传播效果。

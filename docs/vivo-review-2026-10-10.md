# vivo 驳回复核与提交事项

复核依据：用户提供的六张 vivo 驳回截图，报告采集时间 2026-10-08。
复核源码基线：1.0.47 (48)，ce4b6e6；本次修补版本：1.0.48 (49)。

## 已检查和修补

- 两套注册入口均提供可阅读的用户协议、隐私政策和默认不勾选的同意控件，注册提交含协议版本、同意时间。修补备用入口原来的固定 accepted=true 与开发验证码文案。注册版本冲突会取消勾选并提示更新 App，不绕过服务端协议验证；保留表单输入，防止重复提交。
- 当前客户端与生产端的协议版本一致：用户协议 2026-10-02，隐私政策 2026-09-16。注册协议校验通过不等于短信注册全过程已实机通过。
- 充值页 GET /api/auth/payment/channels，仅展示已配置支付渠道。加载失败可重试，未就绪时不能创建订单。生产端支付宝配置齐全且为正式环境，微信支付配置未就绪，最新充值页不展示未配置的微信支付。
- 微信启用后按订单 AppID 注册，检查微信安装和 SDK 唤起结果；支付宝 SDK 返回完成时提示查看余额和订单，不将客户端 SDK 返回替代服务端到账确认。
- 对 1.0.47 真实 APK 读取二进制 Manifest，确认启动入口为原生 PrivacyConsentActivity，application 为 android.app.Application，MainActivity 不对外导出；两个原生协议资产含正确版本。原生门禁同意前不创建 Flutter 引擎。源码回归检查覆盖门禁、入口、共用协议键和版本。
- AI 文本可见标识、分享图片像素标识以及 PNG iTXt AIGC 元数据已有实现，回归检查包含真实 PNG 编码、保留上游生产者和重复写入幂等。详见 ai-labeling-submission.md。

## 仍需提交方操作

1. 使用本次构建包送审，记录 APK 版本/构建号；旧截图无法证明新包运行结果。
2. 首次安装/清除应用数据后做动态隐私检测：未同意、拒绝、阅读协议及返回阶段均不应出现传感器列表读取。代码/Manifest 检查不能代替 vivo 动态检测。
3. 真机使用短信完成注册与登录；真机支付宝充值并核对服务端订单、到账余额。测试未发送短信、创建生产账号或发起真实支付。
4. 如果需要微信支付，先完成商户与开放平台应用配置并核对签名、权限；配置就绪后渠道自动显示，再做真机支付复测。
5. 按 vivo 截图提供资质材料（三种路径按实际条件选择）、AI 生成应用承诺函、显式标识证明和隐式标识说明。资质与盖章不能用代码替代或自行伪造。
6. 显式材料使用送审包运行截图和实际导出的图片；隐式材料读取该图片 AIGC 元数据。不得拿设计图、普通文字或接口 JSON 代替导出文件证明。

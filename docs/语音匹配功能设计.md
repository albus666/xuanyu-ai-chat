# 语音匹配功能设计

根据「按性别匹配（男配女、女配男）、双方同时匹配成功后**一对一**实时语音聊天」的需求，整理实现方案。**语音匹配作为「缘分匹配」模块的第二个工具**，与缘分匹配（喜属性/时辰/年龄/性别/生肖）并列展示在首页。

---

## 一、产品流程

1. **进入匹配**
   - 用户从首页「缘分匹配」区域点击「语音匹配」卡片进入。
   - 校验：已登录、已填性别（`user.gender`：1 男 / 2 女）、未成年人模式未开启时可进入。
   - 用户点击「开始匹配」后进入匹配池，展示「正在为您匹配…」等待态。

2. **匹配池与配对规则**
   - 后端维护两个匹配池：**男池**、**女池**（按 `user.gender` 划分）。
   - 用户进入匹配时写入对应性别池（如 Redis List/Set），并记录加入时间。
   - **配对逻辑**：从男池取 1 人、女池取 1 人，组成一对，两人同时「匹配成功」。
   - 配对成功后生成一条**语音房间**记录（房间 id、双方 user_id、RTC 频道/房间号），并通过推送/长连接通知双方。

3. **匹配成功 → 语音房间**
   - 双方收到「匹配成功」后，跳转到**语音房间页**。
   - 页面展示对方昵称、头像，并自动加入实时语音（仅语音，可后续扩展视频）。
   - 房间内可：**挂断**（结束通话）、**静音**、**举报**。挂断后房间关闭，双方回到匹配入口或消息页。

4. **取消匹配**
   - 用户在「正在匹配」阶段可点击「取消」，从匹配池移除，不再参与本轮配对。

---

## 二、技术选型：实时语音

实时语音需要 **RTC（实时音视频）** 能力，推荐采用第三方云服务，由服务端生成 Token、客户端用 SDK 加入频道。

| 方案 | 说明 | Flutter 集成 |
|------|------|--------------|
| **声网 Agora** | 成熟稳定，国内可用，按分钟计费 | `agora_rtc_engine` 官方包 |
| **腾讯云 TRTC** | 国内延迟低，与云产品体系一致 | `tencent_rtc_sdk` 或官方 Flutter 封装 |
| **网易云信** | 含 IM + 音视频，可和现有 IM 统一 | 官方 Flutter SDK |

建议优先 **Agora** 或 **腾讯云 TRTC**，二者在 Flutter 上都有现成 SDK，接入快。下面以 **Agora** 为例说明端到端流程。

## 三、后端设计

### 3.1 归属服务

语音匹配与语音房间建议放在 **社交服务** 内，与现有 `match`、`im` 同域，例如：

- 匹配池、配对、房间管理：`/api/voice-match`、`/api/voice-room`
- 若 RTC Token 由后端生成：可放在社交服务或单独「系统/配置」服务，仅提供生成 Token 的接口。

### 3.2 匹配池（Redis）

- **Key 设计**
  - 男池：`voice_match:pool:male`（List，元素为 `user_id` 或 JSON：`{"user_id":123,"joined_at":...}`）
  - 女池：`voice_match:pool:female`
- **加入**：用户点击「开始匹配」时，校验性别后 RPUSH 到对应池，并设置用户维度的「正在匹配」标记（如 `voice_match:user:{user_id}` TTL 5 分钟），防止重复入池。
- **取消**：从对应池中移除该 `user_id`，并删除 `voice_match:user:{user_id}`。
- **配对**：可由定时任务（如每 2 秒）或事件驱动：
  - 若 `LLEN voice_match:pool:male` 和 `LLEN voice_match:pool:female` 都 > 0，则 LPOP 各一个，组成一对；
  - 生成 `voice_room` 记录（见下），并通知双方（推送 + 若有用 WebSocket/长连接则推送「匹配成功」事件）。

### 3.3 语音房间与 RTC

- **房间表（MySQL）**  
  例如 `voice_room`：
  - `id`, `room_id`（业务房间号，可与 RTC 的 channel 一致）, `user_id_1`, `user_id_2`, `rtc_channel`（Agora channel name）, `status`(matching/ongoing/ended), `started_at`, `ended_at`, `created_at`
- **RTC Token**
  - 使用 Agora 时：后端用 Agora 服务端 SDK，按 App ID、App Certificate、`channel_name`、`uid` 生成 RTC Token（有时效），接口如：`GET /api/voice-room/join?room_id=xxx` 返回 `{ "room_id", "rtc_token", "channel", "uid", "peer": { "user_id", "nickname", "avatar_url" } }`。
- **加入房间**
  - 客户端收到「匹配成功」后，携带 `room_id` 调 `GET /api/voice-room/join`，拿到 token 与对方信息，再调用 RTC SDK 加入同一 `channel`，即可实时语音。

### 3.4 接口概要

| 接口 | 方法 | 说明 |
|------|------|------|
| 加入匹配池 | POST /api/voice-match/join | 校验性别后入池，返回当前状态（waiting / matched + room_id） |
| 取消匹配 | POST /api/voice-match/cancel | 从池中移除 |
| 轮询/长连接：匹配结果 | GET /api/voice-match/status 或 WS 推送 | 返回 matched + room_id 或 waiting |
| 加入语音房间 | GET /api/voice-room/join?room_id= | 返回 rtc_token、channel、uid、对方信息 |
| 挂断/结束房间 | POST /api/voice-room/leave | 更新房间状态，可选推送对方「对方已挂断」 |

未成年人模式：在「加入匹配池」「加入语音房间」接口中校验用户 `minor_mode`，开启则直接拒绝。

## 四、Flutter 端设计

### 4.1 依赖

```yaml
# pubspec.yaml 增加
dependencies:
  agora_rtc_engine: ^6.3.2   # 以 Agora 为例；或 tencent_rtc_sdk 等
  permission_handler: ^11.3.0  # 已有，用于麦克风权限
```

### 4.2 页面与路由

- **语音匹配入口页**（如 `VoiceMatchPage`）
  - 展示「开始匹配」按钮；匹配中展示「正在匹配…」+「取消」。
  - 轮询 `GET /api/voice-match/status` 或通过 WebSocket 接收「匹配成功」事件，拿到 `room_id` 后跳转 `VoiceRoomPage(roomId)`。
- **语音房间页**（`VoiceRoomPage`）
  - 入参：`room_id`。
  - 请求 `GET /api/voice-room/join?room_id=xxx`，拿到 token、channel、uid、对方信息。
  - 初始化 Agora RTC Engine，加入 channel，开启本地音频发送、订阅远端音频。
  - UI：对方头像/昵称、静音按钮、挂断按钮；挂断时调用 `POST /api/voice-room/leave` 并 `leaveChannel`，然后 pop。

### 4.3 权限与合规

- 进入匹配前或进入房间前请求**麦克风权限**（`permission_handler`）。
- 未成年人模式：在「我的」或设置中已存在；在语音匹配入口根据该状态隐藏或禁用「语音匹配」入口，后端接口也需校验。

### 4.4 目录与入口

- 页面位置：`lib/features/fortune/voice_match_page.dart`、`voice_room_page.dart`（与缘分匹配同属 fortune 模块）
- 入口：首页「缘分匹配」区域第二张卡片「语音匹配 · 一对一语音聊天」
- Agora 配置：`server/Agora.txt` 存 AppID 与证书；客户端仅使用 AppID（见 `lib/core/constants/agora_constants.dart`），证书由服务端生成 Token 使用

## 五、数据流小结

1. 用户 A（男）点击「开始匹配」→ 后端写入男池，返回 waiting。  
2. 用户 B（女）点击「开始匹配」→ 后端写入女池；调度发现男女池各有人，取出 A、B，生成 `voice_room`，写入 Redis/DB，并推送或轮询返回 matched + room_id 给 A、B。  
3. A、B 客户端收到 matched，跳转 `VoiceRoomPage(room_id)`，请求 `join` 拿到 token 与对方信息，用 Agora 加入同一 channel，即可实时语音。  
4. 任一方挂断 → 调 `leave`，更新房间状态，对方收到「对方已离开」并退出房间页。

---

## 六、与现有架构的衔接

- **性别**：沿用 `user.gender`（1 男 / 2 女），从用户服务或 JWT 中获取，匹配池仅按性别分池即可。
- **未成年人模式**：与现有「隐藏发布、信息」逻辑一致，在入口与后端双重校验，不展示或不允许进入语音匹配。
- **IM/举报**：挂断后可引导「加为好友」或「发起聊天」；举报沿用现有 `report` 表，target_type 增加 `voice_room` 或 `voice_match`。

按上述方案即可实现「按性别匹配 + 双方同时匹配成功 + 实时语音聊天」。若你确定采用 Agora 或 TRTC，我可以再按选定 SDK 写出 Flutter 侧加入频道、静音、挂断的示例代码片段。
